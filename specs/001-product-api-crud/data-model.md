# Data Model: Product API — CRUD Microservice

**Phase**: 1 — Design & Contracts  
**Branch**: `001-product-api-crud`  
**Date**: 2026-06-12

## Entities

### Product

Represents a catalog item available for purchase.

| Field            | Type       | Constraints                        | Notes                              |
|------------------|------------|------------------------------------|------------------------------------|
| `Id`             | `Guid`     | Primary key, required              | Generated by application on create |
| `Name`           | `string`   | Required, max 200 chars            |                                    |
| `Description`    | `string?`  | Optional, max 2000 chars           | Nullable                           |
| `Price`          | `decimal`  | Required, >= 0, precision (18, 2)  |                                    |
| `Sku`            | `string`   | Required, unique, max 50 chars     | Unique index in database           |
| `StockQuantity`  | `int`      | Required, >= 0, default 0          |                                    |
| `IsActive`       | `bool`     | Required, default `true`           |                                    |
| `CreatedAtUtc`   | `DateTime` | Required, set on create            | UTC, immutable after creation      |
| `UpdatedAtUtc`   | `DateTime?`| Optional, set on update            | Nullable; UTC                      |

### Validation Rules

| Field           | Rule                                          |
|-----------------|-----------------------------------------------|
| `Name`          | Not empty; max 200 characters                 |
| `Price`         | >= 0                                          |
| `Sku`           | Not empty; max 50 characters; unique globally |
| `StockQuantity` | >= 0                                          |
| `Description`   | Max 2000 characters (if provided)             |

### State Transitions

The Product entity has no formal state machine. `IsActive` is a simple flag toggled by the caller via the update operation. No automated transitions.

## DTOs

### ProductResponse

Returned by GET (single), GET (list), and POST (create).

```
Id, Name, Description, Price, Sku, StockQuantity, IsActive, CreatedAtUtc, UpdatedAtUtc
```

### CreateProductRequest

Submitted to POST /api/products.

```
Name (required), Description (optional), Price (required), Sku (required),
StockQuantity (optional, default 0), IsActive (optional, default true)
```

### UpdateProductRequest

Submitted to PUT /api/products/{id}. Full replacement semantics — all fields required.

```
Name (required), Description (optional), Price (required), Sku (required),
StockQuantity (required), IsActive (required)
```

### PagedResult\<T\>

Generic wrapper returned by GET /api/products.

```
Items: T[], TotalCount: int, PageNumber: int, PageSize: int
```

## Database Schema

### Table: `products`

```sql
CREATE TABLE products (
    id               UUID         NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
    name             VARCHAR(200) NOT NULL,
    description      VARCHAR(2000),
    price            NUMERIC(18,2) NOT NULL,
    sku              VARCHAR(50)  NOT NULL,
    stock_quantity   INT          NOT NULL DEFAULT 0,
    is_active        BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at_utc   TIMESTAMP    NOT NULL,
    updated_at_utc   TIMESTAMP
);

CREATE UNIQUE INDEX ix_products_sku ON products (sku);
```

> Note: The actual DDL is generated by EF Core migrations; the above is for documentation clarity.

## Repository Interface

```
IProductRepository:
  GetByIdAsync(Guid id, CancellationToken)           → Product?
  GetPagedAsync(int pageNumber, int pageSize, ct)    → (IReadOnlyList<Product>, int totalCount)
  SkuExistsAsync(string sku, CancellationToken)      → bool
  AddAsync(Product product, CancellationToken)       → void
  Update(Product product)                            → void
  Remove(Product product)                            → void
  SaveChangesAsync(CancellationToken)                → int
```

## Dependency Direction

```
Product.Api
    │
    ├──► Product.Application  (IProductService, ProductService, DTOs, validators)
    │         │
    │         └──► Product.Domain  (Product entity, IProductRepository)
    │                   ▲
    └──► Product.Infrastructure  (ProductDbContext, ProductRepository, migrations)
```

`Domain` has zero external dependencies. `Infrastructure` and `Application` depend only on `Domain`. `Api` wires up DI for both `Application` and `Infrastructure`.
